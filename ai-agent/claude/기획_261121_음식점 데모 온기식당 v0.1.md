# 한식 밥집 데모 기획: 온기식당

**파일 위치**: `ai-agent/claude/기획_261121_음식점 데모 온기식당 v0.1.md`
**작성일**: 2026-11-21
**버전**: v0.1
**설명**: 포트폴리오에 넣을 가상의 동네 한식 밥집 "온기식당" 데모의 목표, 범위, 화면, 저장 방식, 결정 기록. 상위 기획서의 R-13, D-09, D-12에 대응한다.

---

## 1. 목표와 이유

- 상담 중 "작업물 보여 주세요"에 링크를 바로 보낼 수 있게 업종별 데모를 갖춘다 (D-09). 받고 싶은 의뢰인은 음식점·학원 같은 동네 소상공인이다. 학원 데모(바른길 학원) 다음으로 음식점 데모를 만든다.
- 데모 4개가 서로 다른 기능을 보여 주게 한다: 하루밀 = 보기만 하는 홈페이지, 바른길 학원 = 문의 신청과 관리, 살롱 결 = 서버 예약. 이 데모는 **사장님이 메뉴를 직접 관리**하는 기능을 보여 준다.
- 이유: 음식점 사장님이 가장 자주 묻는 것이 "메뉴나 가격이 바뀌면 제가 직접 고칠 수 있나요?"다 (상담 연습에서도 나왔다). 이 데모가 그 질문에 링크 하나로 답한다.
- 핵심 장면: 사장님 화면에서 "고등어구이 정식"을 **품절**로 바꾸고 [손님 화면 보기]를 누르면, 손님 메뉴판에 바로 품절 표시가 붙어 있다. 사진을 바꾸거나 오늘의 백반을 고쳐도 같은 식으로 바로 반영된다.
- 포트폴리오 가격: **DELUXE(80만 원~)** 예시 (D-11).
- 성공 기준: 동네 밥집 사장님이 링크를 눌러 품절 스위치를 직접 눌러 보고 "우리 가게도 이렇게 해 달라"며 플랫폼으로 문의하는 것.

## 2. 범위

| 구분 | 포함 | 제외 |
|------|------|------|
| 손님 | 가게 공지, 첫 화면과 오늘의 백반, 메뉴판(사진·품절 표시), 가게 이야기, 영업 안내, 오시는 길 | 온라인 주문·결제, 테이블 예약, 리뷰 |
| 사장님 | 가게 공지 쓰기·켜고 끄기, 오늘의 백반 고치기, 메뉴 추가·수정·삭제, 품절 스위치, **메뉴 사진 올리기·바꾸기·빼기**, 처음 메뉴로 되돌리기 | 로그인(데모라서 없음), 영업시간 수정, 매출·주문 통계 |
| 저장 | 방문자 브라우저 안(localStorage)에만 (D-09) | 서버·DB |
| 가게 | 지어낸 가게 "온기식당" (동네 한식 백반·찌개·정식집) | 실제 가게 |

**안티 목표** (기술적으로 돌아가도 실패로 보는 것)
- 링크를 눌렀는데 느리게 뜨는 것 (사진이 무거운 것 포함)
- 방문자가 남이 고친 메뉴·올린 사진을 보는 것
- 실제 가게나 실제 연락처로 오해받는 것 (D-02)
- 사진을 올리다 저장 공간이 넘쳐서 데모가 조용히 깨지는 것 (메뉴가 사라지거나 고친 내용이 저장되지 않는데 아무 안내가 없는 것)
- 하루밀·살롱 결·바른길 학원·포트폴리오 본체와 같은 디자인처럼 보이는 것
- 휴대폰에서 메뉴 줄이 넘치거나 품절 스위치가 손가락으로 누르기 어려운 것

## 3. 만드는 방법

### 접근 비교

데모 방식은 상위 결정 D-09를 따른다 (운영자가 A를 골랐다).

| 안 | 내용 | 결과 |
|----|------|------|
| **A. 브라우저 안에서만 동작** | 포트폴리오 `src/demos/` 안의 정적 페이지, localStorage 저장 | **선택**: 0원, 링크가 바로 열림, 방문자마다 자동 분리 |
| B. 별도 FastAPI 서버 | 새 프로젝트 + Render | Render 무료 시간이 서버 한 대분이라 탈락 |
| C. 살롱 결 서버에 얹기 | 서버 하나로 두 데모 | 두 데모가 엉켜 탈락 |

보여 줄 기능은 (1) 보기만 하는 홈페이지(하루밀과 겹침), (2) 단체·포장 주문 문의(학원의 신청·관리 흐름과 겹침), (3) 사장님 메뉴 직접 관리 중 **(3)을 골랐다** (운영자). 업종은 한식 밥집 / 고깃집 / 메뉴 많은 분식·국밥집 중 **한식 밥집**을 골랐다 (운영자). 오늘의 백반과 재료 소진 품절이 매일 일어나는 업종이라 핵심 장면이 가장 자연스럽다.

메뉴 사진 저장 방법 (Claude 결정, 아래 §5): 올린 사진을 브라우저에서 작게 줄여 localStorage에 넣는다. IndexedDB는 저장 공간이 넓지만 코드가 복잡해지고, 장수를 제한하면 localStorage로 충분하다.

### 정해진 것

- 순수 HTML·CSS·바닐라 JS, 빌드 도구 없음 (D-01). 프로젝트 코드 작성 규칙(파일 헤더, `style=""` 금지, 색은 `:root` 변수만, 접근성 기본)을 따른다.
- 분위기: **시안 A 먹색 + 한지**. 미색 한지 배경(`#f6f1e7` 계열), 먹색 글씨(`#2b2622` 계열), 품절·공지는 붉은 도장색(`#b23a2b` 계열). 제목은 Noto Serif KR, 본문은 Pretendard. 오늘의 백반은 먹색 판에 미색 글씨. 메뉴판은 점선으로 나눈 줄.
- 연락처·주소는 누가 봐도 가짜 (`000-0000-0000`, "OO시 OO구 OO로 00"). 인스타 링크는 `href="#"`.
- `<meta name="robots" content="noindex">`.
- 위쪽에 데모 띠: "포트폴리오용 데모예요 · 손님 화면 / 사장님 화면".
- 기본 메뉴 사진과 가게 사진은 무료 사진 사이트에서 내려받아 줄여 `assets/`에 두고 `CREDITS.md`에 출처를 적는다 (핫링크 금지). 내려받기 전에 목록과 출처를 운영자에게 보여 주고 허락을 받는다.
- 데스크톱(1280px)과 휴대폰(375px)에서 확인한다.
- 포트폴리오 `index.html` 사례 목록에 카드를 더하고 "라이브 데모 보기"를 단다. 카드용 스크린샷 1280·375는 `ai-agent/scripts/screenshot.py`로 찍는다.

## 4. 화면 구성

### 손님 화면 (`index.html`)

| ID | 섹션 | 내용 |
|----|------|------|
| G-01 | 상단 메뉴 | 가게 이름, 메뉴·오늘의 백반·영업 안내·오시는 길 이동. 휴대폰에서는 ☰ 메뉴 |
| G-02 | 가게 공지 띠 | 사장님이 켠 공지 한 줄을 붉은 띠로 맨 위에 ("오늘은 재료 소진으로 저녁 8시에 마감해요"). 꺼져 있으면 보이지 않는다 |
| G-03 | 첫 화면 + 오늘의 백반 | "갓 지은 밥 한 그릇, 매일 바뀌는 집밥 반찬". 먹색 판에 오늘 날짜, 반찬 구성, 가격, 점심 시간 |
| G-04 | 메뉴판 | [식사·찌개·정식·추가] 탭. 메뉴마다 사진(있을 때만, 작은 정사각형), 이름, 한 줄 설명, 가격. 품절이면 취소선과 붉은 "품절" 표시, 흐리게 |
| G-05 | 가게 이야기 | 가게 사진 1장과 짧은 글 ("매일 아침 시장에서 장 봐서 차리는 밥상") |
| G-06 | 영업 안내 | 영업시간, 브레이크 타임, 휴무일, 단체석, 포장 가능 |
| G-07 | 오시는 길·바닥글 | 가짜 주소·전화, 지도 대신 그림, 데모 안내, 사진 출처, 포트폴리오로 돌아가기 |

### 사장님 화면 (`owner.html`)

| ID | 화면 | 내용 |
|----|------|------|
| M-01 | 가게 공지 | 공지 한 줄 입력, [손님 화면에 보이기] 켜고 끄기, 저장 |
| M-02 | 오늘의 백반 | 반찬 구성과 가격 고치기, 저장. 날짜는 오늘로 자동 |
| M-03 | 메뉴 목록 | 분류별 메뉴 줄. 줄마다 사진 미리보기, 이름·가격, **판매중/품절 스위치**, [수정] [삭제]. 방금 바꾼 줄은 잠깐 강조("방금 품절로 바꿨어요") |
| M-04 | 메뉴 추가·수정 | 이름, 가격, 한 줄 설명, 분류, 사진(선택). 같은 칸을 추가·수정에 함께 쓴다. 삭제는 한 번 더 묻는다 |
| M-05 | 메뉴 사진 | [사진 올리기] / [사진 바꾸기] / [사진 빼기]. 올리면 바로 미리보기. 처리 중에는 "사진 줄이는 중" 표시 |
| M-06 | 데모 안내 | "데모라 이 브라우저에만 저장돼요. 실제 서비스에서는 서버에 저장되어 모든 손님 휴대폰에 바로 반영돼요" + [처음 메뉴로 되돌리기] |

## 5. 저장과 규칙

- 저장 위치: localStorage 키 하나에 JSON (`{ version, createdAt, notice: {text, visible}, todaySet: {dishes, price}, menus: [...] }`). 메뉴 하나는 `id, name, price, description, category, soldOut, photo, updatedAt`. `photo`는 기본 사진이면 `assets/` 경로, 사장님이 올린 사진이면 줄인 JPEG 데이터 주소(data URL), 없으면 빈 값.
- 처음 들어오거나 데이터가 없으면 기본 메뉴 12개 안팎을 만든다. 대표 메뉴 6개 정도에는 기본 사진이 있고, 1개는 처음부터 품절로 둬서 품절 모양을 바로 볼 수 있게 한다.
- 만들어진 지 24시간이 지나면 처음 메뉴로 되돌린다 (학원·살롱 결과 같은 수명).
- 메뉴는 40개까지 (장난 입력 대비). 가격은 0원 초과 100만 원 미만 정수, 이름은 1~20자, 설명은 40자까지.
- **사진 규칙** (Claude 결정)
  - 이미지 파일(jpg·png·webp)만 받는다. 올리면 브라우저 안에서 긴 변 600px로 줄이고 JPEG 품질 0.75로 다시 저장한다 (canvas). 한 장 약 100KB 이하가 목표, 줄인 뒤에도 200KB를 넘으면 더 낮은 품질로 한 번 더 줄인다.
  - 사장님이 올린 사진은 **최대 10장**. 넘으면 "데모에서는 사진을 10장까지 올릴 수 있어요" 안내.
  - 저장 공간이 넘치면(QuotaExceededError) 바꾸기 전 상태를 그대로 두고 "저장 공간이 부족해요. 사진을 몇 장 빼고 다시 해 주세요" 안내를 띄운다. 일부만 저장되는 일이 없게 한다.
  - 포트폴리오 사이트 전체(같은 주소)가 저장 공간을 함께 쓰므로, 학원 데모와 키가 겹치지 않게 데모마다 다른 키를 쓴다.
- localStorage를 쓸 수 없는 브라우저에서는 메모리에만 두고 "이 브라우저에서는 새로 고치거나 화면을 옮기면 바뀐 내용이 사라져요" 안내를 띄운다.
- 다른 탭에서 바뀐 내용은 `storage` 이벤트로 손님 화면에 바로 반영한다 (두 탭을 나란히 열어 품절 스위치를 눌러 보는 방문자를 위해).
- 손님 화면의 가격은 `9,000`처럼 천 단위 쉼표로 보여 준다.

## 6. 만드는 사람이 정할 것

- 색 값 세부, 화면 배치 세부 (시안 A와 구성 초안 그림 기준)
- 메뉴 이름·가격·설명, 오늘의 백반 반찬, 가게 이야기 문구, 영업시간 (지어낸 내용, 동네 한식 밥집 수준. 백반 9,000원 안팎)
- 기본 사진 고르기 (같은 톤, 한식 백반·찌개·생선구이 등)
- 파일 구조. 제안: `src/demos/ongi-sikdang/` 아래 `index.html`, `owner.html`, `css/style.css`, `js/store.js`(저장·기본 메뉴·24시간 규칙·사진 줄이기, 두 화면 공용), `js/main.js`(메뉴·탭·손님 화면 그리기), `js/owner.js`(사장님 화면), `assets/`
- 메뉴판 탭 방식(눌러서 거르기 / 눌러서 해당 분류로 이동)
- 확인 방법: 1280·375 화면에서 가로 넘침 없음, 콘솔 오류 없음. 품절 켜기 → 손님 화면 반영, 메뉴 추가·수정·삭제, 사진 올리기(큰 사진 포함)·바꾸기·빼기, 11번째 사진 거절, 공지 켜고 끄기, 새로 고침 후 유지, 처음 메뉴로 되돌리기까지 직접 눌러 본다.
- 포트폴리오 카드 위치 (제안: 바른길 학원 다음)
