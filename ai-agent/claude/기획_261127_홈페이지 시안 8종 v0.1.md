## 1. 목표와 이유

- 크몽에서 홈페이지 제작으로 수익을 낸다. 시안을 미리 만들어 두고 고객이 그중 하나를 고르게 하면, 상담과 디자인 시안 단계가 짧아져 **빨리 팔고 빨리 납품**할 수 있다 (운영자).
- 그래서 이번 시안은 **기능보다 디자인 완성도**가 중요하다 (운영자). 지금까지의 데모 4개(하루밀·살롱 결·바른길 학원·온기식당)는 "기능까지 동작하는 사례"였고, 이번 시안은 "고르는 디자인 견본"이다. 기존 데모는 시안 목록에 넣지 않고 새로 만든다 (운영자).
- 고객은 **업종**으로 시안을 찾고, 같은 업종 안에서도 시안마다 **분위기가 확실히 다르게** 보여야 한다 (운영자).
- 고객에게는 **크몽 상세페이지 이미지로만** 보여 준다. 링크는 걸지 않는다 (운영자, 안 B).
- 성공 기준: 고객이 상세페이지 이미지를 보고 "3번으로 해 주세요"라고 말하고, 운영자는 그 시안 폴더를 복사해 글·사진·색만 바꿔 며칠 안에 납품한다.

**안티 목표** (만들어져도 실패로 보는 것)
- 8개가 같은 틀에 색만 바꾼 것처럼 보이는 것 (배치·글꼴·사진 쓰는 법까지 달라야 한다)
- 스크린샷이 어둡거나 사진이 칙칙해서 이미지로 봤을 때 매력이 떨어지는 것 (운영자가 5·6번을 "어둡다"고 두 번 고쳤다)
- 도형·색 덩어리만 있고 사진이 없어 "와닿지" 않는 것 (7번 피드백)
- 고객이 고른 뒤 고칠 곳을 찾느라 시간이 오래 걸리는 것

- 휴대폰 화면에서 글이 넘치거나 겹치는 것
- 기존 데모 4개나 포트폴리오 본체와 같은 디자인처럼 보이는 것

## 3. 만드는 방법

### 접근 비교

| 안 | 내용 | 결과 |
|----|------|------|
| **A. 시안마다 완결된 폴더** | `01-company/`에 `index.html`·`style.css`·`main.js`·`assets/`가 다 들어 있다 | **선택 (운영자)**: 고르면 폴더 하나를 복사해 고치면 된다. 다른 시안에 영향이 없다. 지금 사이트와 같은 순수 HTML·CSS라 배우며 고치기 쉽다. 공통 코드가 8번 반복되는 것은 감수한다 |
| B. 글을 데이터 파일에 두고 JS로 그리기 | `content.js` 하나만 고치면 글이 바뀐다 | 탈락: 구조가 복잡하고, 화면을 JS가 그려 검색엔진이 내용을 읽기 어렵다. 고객 홈페이지에 맞지 않는다 |
| C. 공통 CSS + 시안별 꾸밈 CSS | 반복 코드가 줄어든다 | 탈락: 납품할 때 공통 파일을 챙겨야 하고, 공통 파일을 고치면 8개가 같이 바뀐다. 분위기가 크게 다른 이번 시안에는 불편하다 |

보여 주는 방법도 비교했다: (A) 포트폴리오에 "시안 고르기" 페이지 + 링크, (B) 크몽 상세페이지 이미지로만, (C) 둘 다. **운영자가 B를 골랐다.**

### 정해진 것

- 순수 HTML·CSS·바닐라 JS, 빌드 도구 없음 (D-01). 프로젝트 코드 작성 규칙(파일 헤더, `style=""` 금지, 색은 `:root` 변수만, 시맨틱 태그, 이미지 `alt`, 버튼 `aria-label`)을 따른다.
- **두는 곳**: 별도 비공개 저장소 `homepage-templates` (운영자 결정, D-T5). 로컬 폴더는 `C:\Users\PC2602\homepage-templates`, GitHub는 `waterdog-hub/homepage-templates` (Private). 저장소 이름과 위치는 Claude 제안. GitHub 저장소 만들기는 구현 시작 때 운영자 허락을 받고 한다. 파는 상품의 원본(코드·사진)이 공개 저장소에 올라가지 않게 하려는 것이다. 이 기획 문서와 분위기 견본은 다른 기획 문서처럼 portfolio-site의 `ai-agent/claude/`에 둔다 (디자인 설명일 뿐 상품 원본은 아니다).
- **시안 번호**: `T-01`~`T-08`. 크몽 이미지와 납품 대화에서 이 번호를 쓴다 (Claude 결정, 고객이 "3번"처럼 말하기 쉽게).
- **글꼴**: 본문은 모두 Pretendard (jsDelivr CDN). 제목 글꼴은 시안별로 다르게 (§5). 구글 폰트 CDN을 쓴다.
- **고칠 곳 표시**: 납품 때 바꾸는 글·사진·색에 `<!-- 바꿀 곳: 상호 -->` 같은 주석을 단다. 색은 `style.css` 맨 위 `:root`에 모두 모은다. 시안 폴더마다 `README.md`에 "고객 맞춤 순서"(상호 → 색 → 사진 → 글 → 연락처)를 적는다 (Claude 결정, 납품 시간을 줄이는 핵심).
- **지어낸 내용**: 상호·숫자는 모두 지어낸 것. 전화는 `000-0000-0000`, 주소는 "OO시 OO구 OO로 00", 이메일·SNS는 `href="#"`. **사진 속 인물에는 이름을 붙이지 않는다**: 의료진·변호사·코치 카드는 "OOO 대표원장"처럼 이름 자리로 둔다 (Claude 결정, 실제 사진 모델이 지어낸 의사·변호사로 오해받지 않게. 납품 때 고객의 실제 사진과 이름으로 바꾸는 자리이기도 하다).
- **지도**: 실제 지도 대신 지도 자리 그림(회색 상자 + 핀 아이콘). 납품 때 고객 주소로 카카오·네이버 지도 넣기는 `README.md`에 안내만 한다.
- **문의 버튼**: 시안 안의 "문의/예약" 버튼은 `href="#contact"`로 페이지 아래 연락처 구역으로 간다. 이 시안은 고객의 홈페이지가 되는 것이라 D-02(운영자 연락처 금지)와는 상관없지만, 견본에는 가짜 연락처만 넣는다.
- **검색 노출**: `<meta name="robots">`는 넣지 않는다 (고객 홈페이지가 될 파일이라 검색되어야 한다). 배포하지 않으니 견본이 검색될 일은 없다.
- **사진**: Unsplash에서 내려받아 가로 최대 1600px(작은 사진 800px), JPEG 품질 80 안팎으로 줄여 `assets/`에 둔다. 출처(사진 주소, 작가)를 `assets/CREDITS.md`에 적는다. **내려받기 전에 시안별 사진 목록을 운영자에게 보여 주고 허락을 받는다.** 8개 시안의 목록을 한 번에 보여 주고 한 번에 허락받는다 (Claude 결정, 확인 횟수를 줄이려고). 분위기 견본에 쓴 사진 ID(§5)를 출발점으로 쓰되, 더 맞는 사진이 있으면 바꿔도 된다.
- **밝기**: 사진은 밝고 선명한 것을 고른다. 어두운 사진 위에 글을 얹을 때만 그라데이션을 덮는다 (T-01, T-08은 의도된 어두운 분위기).
- **확인**: 데스크톱 1280px와 휴대폰 375px에서 확인한다. `py -3 -m http.server 8000`을 저장소 루트에서 띄우거나 `index.html`을 바로 연다 (ES 모듈을 쓰지 않으니 `file://`로도 열린다).
- **크몽용 스크린샷**: portfolio-site의 `ai-agent/scripts/screenshot.py`를 새 저장소 `scripts/shot.py`로 복사해 쓴다. 이 스크립트는 지금 화면 높이만큼만 찍으므로 **전체 페이지를 찍는 옵션을 더한다** (CDP `Page.getLayoutMetrics`로 높이를 재고 `captureBeyondViewport`). 결과는 `_shots/T-01-1280.jpg`, `T-01-375.jpg`처럼 둔다. 선명하게 보이도록 2배 해상도(`deviceScaleFactor: 2`)로 찍고, 긴 전체 이미지와 함께 일정 높이로 나눈 조각 이미지도 만든다 (Claude 결정). 크몽 상세 이미지의 실제 크기·용량 제한은 상세페이지를 꾸밀 때(이번 범위 밖) 확인한다. 원본이 크고 조각도 있으면 그때 줄이거나 잘라 쓰면 된다.
