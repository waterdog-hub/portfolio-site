# 온기식당 데모 구현 계획

**파일 위치**: `ai-agent/claude/계획_261121_온기식당 구현.md`
**작성일**: 2026-11-21

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 가상의 동네 한식 밥집 "온기식당"의 손님 화면과 사장님 메뉴 관리 화면(메뉴·가격·품절·사진·오늘의 백반·공지)을 `src/demos/ongi-sikdang/`에 서버 없이 만들고, 포트폴리오에 라이브 데모 카드로 연결한다.

**Architecture:** 빌드 도구 없는 정적 페이지 2장(`index.html`, `owner.html`). 저장·기본 메뉴·규칙은 DOM을 모르는 ES 모듈 `js/store.js`에 모아 `node --test`로 검증한다. 사진 줄이기는 canvas가 필요해 브라우저 전용 모듈 `js/photo.js`로 따로 둔다. 화면 스크립트(`main.js`, `owner.js`)는 store를 불러 그리기만 한다. 데이터는 방문자 브라우저 localStorage에만 둔다.

**Tech Stack:** HTML, CSS(변수·Flex·Grid·미디어쿼리), 바닐라 JS(ES 모듈), localStorage, canvas, Google Fonts(Noto Serif KR), Pretendard(jsDelivr), Node 26 `node:test`(개발용, 배포되지 않음)

**Spec:** `ai-agent/claude/기획_261121_음식점 데모 온기식당 v0.1.md` (상위 결정 D-09, D-12)

## Global Constraints

- 파일 최상단 헤더: 작성일, 파일 위치, 목적. 새 코드에는 *왜*를 한두 줄 주석으로 (운영자 학습용)
- HTML에 `style=""` 금지. 색은 `css/style.css` 맨 위 `:root` 변수만. 이미지 `alt`, 버튼 `aria-label`, 시맨틱 태그
- 사용자가 넣은 글(메뉴 이름·설명·공지·반찬)은 `textContent`로만 화면에 넣는다. 사용자 값을 `innerHTML`에 넣지 않는다
- 분위기: 시안 A 먹색 + 한지. 한지 배경 `#f6f1e7` 계열, 먹색 글씨 `#2b2622` 계열, 품절·공지 붉은 도장색 `#b23a2b` 계열, 오늘의 백반 판은 먹색 바탕에 미색 글씨. 제목 Noto Serif KR, 본문 Pretendard. 메뉴판은 점선으로 나눈 줄. 본문 글자 대비 WCAG AA(4.5:1)
- 연락처는 누가 봐도 가짜: 전화 `000-0000-0000`, 주소 "OO시 OO구 OO로 00", 인스타 `href="#"`
- 모든 화면 위쪽 데모 띠: "포트폴리오용 데모예요 · 손님 화면 / 사장님 화면". 바닥글: "포트폴리오용 데모 사이트입니다. 가게·메뉴·연락처는 모두 지어낸 예시입니다.", 사진 출처, 포트폴리오(`../../index.html`)로 돌아가기
- `<meta name="robots" content="noindex">`
- localStorage 키 `ongi-sikdang-demo-v1` (학원 데모 `bareun-academy-demo-v1`과 겹치지 않게). 수명 24시간
- 메뉴 규칙: 40개까지, 이름 1~20자, 가격 1 이상 1,000,000 미만 정수(입력의 쉼표 허용), 설명 40자까지, 분류는 `meal`(식사)·`stew`(찌개)·`set`(정식)·`extra`(추가)
- 사진 규칙: jpg·png·webp만, 긴 변 600px·JPEG 품질 0.75로 줄이고, 결과가 200KB를 넘으면 품질 0.6으로 한 번 더. 사장님이 올린 사진(`data:`로 시작) 10장까지. 저장 공간이 넘치면 바꾸기 전 상태 유지 + "저장 공간이 부족해요. 사진을 몇 장 빼고 다시 해 주세요"
- 기본 사진: 내려받아 줄여 `assets/`에(핫링크 금지), 한 장 300KB 이하(메뉴 사진은 가로 600px), 내려받기 전에 운영자 허락, 출처 `assets/CREDITS.md`
- 화면 확인은 로컬 서버로: `py -3 -m http.server 8000 -d src` 후 `http://localhost:8000/demos/ongi-sikdang/`
- 확인 너비 1280px, 375px. 375px에서 `document.documentElement.scrollWidth <= innerWidth`. 품절 스위치 누르는 영역은 44x44px 이상
- 테스트: 저장소 루트에서 `node --test tests/`
- 커밋은 기능 브랜치 `feat/local-shop-demos`에서 운영자 승인 후, Conventional Commits. `main` 병합·푸시(=Netlify 배포)는 운영자 승인 후

## Review Focus

1. **사진을 올리다 저장 공간이 넘침**: 메뉴·다른 사진이 사라지거나 반만 저장되면 안 되고, 바꾸기 전 화면이 그대로 남고 안내가 떠야 한다 → Task 1 테스트 `commit_quota_keeps_previous`
2. **휴대폰으로 찍은 큰 사진(4000px, 5MB 이상)이나 사진이 아닌 파일을 올림**: 큰 사진은 줄어서 들어가고, 사진이 아니면 "사진 파일만 올릴 수 있어요" → Task 3 확인 단계
3. **가격을 "9,000"이나 " 9000 "처럼 넣음**: 9000으로 받아들여야 하고, "구천"·"0"·"-500"은 가격 칸 오류 → Task 2 테스트 `parsePrice`
4. **메뉴 이름·공지에 HTML을 넣음**: 글자 그대로 보이고 실행되지 않아야 한다 → Task 5 확인 단계
5. **한 분류의 메뉴를 모두 지움**: 손님 메뉴판의 그 탭에 "준비 중인 메뉴예요"가 보이고 깨지지 않아야 한다 → Task 4 확인 단계
