**설명**: 포트폴리오에 넣을 가상의 초·중등 보습학원 "바른길 학원" 데모의 목표, 범위, 화면, 저장 방식, 결정 기록. 상위 기획서의 R-12, D-09, D-10에 대응한다.

## 1. 목표와 이유

- 크몽 상담 중 의뢰인이 "작업물 보여 주세요"라고 하면 **링크 2~3개를 바로 보낼 수 있게** 업종별 예시 홈페이지를 갖춘다 (상담 연습 피드백, 2026-11-21).
- 받고 싶은 의뢰인은 **음식점·학원 같은 동네 소상공인 사장님**이다 (운영자). 이미 있는 데모는 카페(하루밀, 보기만 하는 페이지)와 미용실(살롱 결, 예약)뿐이다. 이 문서는 학원 데모를 다루고, 음식점 데모는 별도 기획서로 뒤이어 만든다.
- 학원 홈페이지를 실제로 보는 사람은 **학생이 아니라 학부모**다. 그래서 핵심 기능은 "학부모 상담 신청 → 원장님이 관리"다.
- 핵심 장면: 방문자가 학부모 화면에서 상담을 신청하고 [원장님 화면에서 확인해 보기]를 누르면, **방금 넣은 신청이 "방금 들어온 신청"으로 맨 위에 있고 상태를 바꿀 수 있다.** (살롱 결의 핵심 장면을 서버 없이 보여 준다.)
- 포트폴리오 가격과의 연결: 상담 신청 폼과 관리 화면이 붙은 **DELUXE(80만 원~) 수준**의 예시다. 하루밀은 STANDARD, 살롱 결은 DELUXE 이상(서버 예약) 예시로 둔다.
- 성공 기준: 학원 원장님이 링크를 눌러 몇 초 안에 화면을 보고, "우리 학원도 이렇게 상담받고 싶다"며 플랫폼으로 문의하는 것.

## 2. 범위

| 구분 | 포함 | 제외 |
|------|------|------|
| 학부모 | 학원 소개, 강좌·시간표(과목·요일·시간·남은 자리), 강사 소개, 수업 방식, 상담 신청, 신청 완료 안내 | 회원가입, 수강료 결제, 온라인 수업, 성적 조회 |
| 원장님 | 상담 신청 목록, 상태별 개수와 필터, 상태 바꾸기, 메모, 예시로 되돌리기 | 로그인(데모라서 없음), 강좌·시간표 수정, 출결·수납 관리 |
| 알림 | 없음. 화면에 "실서비스에서는 서버에 저장하고 원장님 휴대폰으로 알림톡을 보내요" 안내만 | 문자·알림톡·이메일 발송 |
| 저장 | 방문자 브라우저 안(localStorage)에만 (D-09) | 서버·DB |
| 학원 | 지어낸 학원 "바른길 학원" (초·중등 수학·영어) | 실제 학원 |
| 후기 | 넣지 않는다 (아래 안티 목표) | 학부모 후기, 성적 향상 사례 |

**안티 목표** (기술적으로 돌아가도 실패로 보는 것)
- 링크를 눌렀는데 몇 초 이상 하얀 화면이 나오는 것 (서버가 잠들어 있다 깨는 등)
- 방문자가 남이 넣은 신청·이름을 보는 것
- 실제 학원이나 실제 연락처로 오해받는 것 (D-02). 지어낸 후기·성적 사례가 "가짜 후기"처럼 보이는 것
- 하루밀·살롱 결·포트폴리오 본체와 같은 디자인처럼 보이는 것
- 휴대폰에서 시간표 줄이 넘치거나 가로 스크롤이 생기는 것

## 3. 만드는 방법

### 접근 비교 (운영자가 A를 골랐다)

| 안 | 내용 | 장점 | 단점 |
|----|------|------|------|
| **A. 브라우저 안에서만 동작** | 포트폴리오 `src/demos/` 안의 정적 페이지. 신청은 방문자 브라우저 localStorage에 저장 | 0원, 링크가 바로 열림, 방문자마다 자동 분리, 서버 관리 없음 | 진짜 서버는 아님 (백엔드 실력은 살롱 결이 보여 준다) |
| B. 별도 FastAPI 서버 | 살롱 결과 같은 새 프로젝트 + Render | 진짜 백엔드 | Render 무료 750시간은 한 대분이라 둘 중 하나는 잠들어 첫 접속이 약 1분 걸림, 아니면 유료 |
| C. 살롱 결 서버에 얹기 | 서버 하나로 두 데모 | 무료, 진짜 백엔드 | 두 데모가 엉켜 하나 고치다 다른 쪽이 깨질 수 있음 |

### 정해진 것

- 순수 HTML·CSS·바닐라 JS, 빌드 도구 없음 (D-01). 프로젝트 코드 작성 규칙(파일 헤더, `style=""` 금지, 색은 `:root` 변수만, 접근성 기본)을 따른다.
- 분위기: **시안 A 신뢰 네이비**(남색 `#1f3a68` 계열 + 흰색, 정보·숫자 중심) 위에 **시안 C의 시간표 줄**(과목·학년 / 요일·시간 / 남은 자리)을 얹는다. 글꼴은 Pretendard 하나 (하루밀·살롱 결의 명조 제목과 구별). 남은 자리 강조는 주황 계열 한 색.
- 연락처·주소는 누가 봐도 가짜 (`000-0000-0000`, "OO시 OO구 OO로 00").
- `<meta name="robots" content="noindex">` (하루밀과 같다).
- 위쪽에 데모 띠: "포트폴리오용 데모예요 · 학부모 화면 / 원장님 화면" (두 화면을 오가는 링크).
- 데스크톱(1280px)과 휴대폰(375px)에서 확인한다.
- 포트폴리오 `index.html` 사례 목록에 카드를 더하고 "라이브 데모 보기"를 단다. 카드용 스크린샷 1280·375는 `ai-agent/scripts/screenshot.py`로 찍는다.

## 5. 저장과 규칙

- 저장 위치: localStorage 키 하나에 JSON (`{ version, createdAt, inquiries: [...] }`). 신청 하나는 `id, parentName, phone, grade, subject, preferredTime, message, status, memo, createdAt, isSample`.
- 상태: `new`(새 신청) → `contacted`(연락함) → `enrolled`(등록) / `onhold`(보류). 원장님은 어느 상태에서든 다른 상태로 바꿀 수 있다 (실제로 되돌릴 일이 있어서).
- 처음 들어오거나 데이터가 없으면 예시 신청 5~6건을 만든다 (상태를 섞고, 신청 시각은 "지금"에서 몇 시간·며칠 전으로 계산해 늘 최근처럼 보이게).
- 만들어진 지 24시간이 지나면 예시로 되돌린다 (살롱 결과 같은 수명).
- 방문자가 직접 넣는 신청은 20건까지. 넘으면 안내만 띄운다.
- 학부모 화면 폼의 이름·연락처는 "예시 이름"·"000-0000-0000"을 미리 채우고 "실제 정보를 넣지 마세요"라고 안내한다. 연락처는 형식만 가볍게 확인한다.
- localStorage를 쓸 수 없는 브라우저(일부 사생활 보호 모드)에서는 메모리에만 두고 "이 브라우저에서는 새로 고치면 신청이 사라져요" 안내를 띄운다. 학부모 화면에서 원장님 화면으로 넘어갈 때 사라지므로 핵심 장면이 안 된다는 점도 안내 문구에 담는다.
- 다른 탭에서 바뀐 내용은 `storage` 이벤트로 원장님 화면에 반영한다 (두 탭을 나란히 열어 보는 방문자를 위해).
