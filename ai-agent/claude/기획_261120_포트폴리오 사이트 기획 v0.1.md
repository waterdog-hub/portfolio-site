## 1. 목표

- 크몽·숨고 의뢰인이 서비스 페이지에서 링크를 눌러 들어와 **"이 사람에게 맡겨도 되겠다"** 고 판단하게 한다.
- 주력: **웹 제작** (홈페이지·랜딩페이지 + 예약·문의·관리자 같은 백엔드 기능).
- 차별점: 화면만 만드는 퍼블리셔와 달리 **백엔드(Python·SQL)까지 한 사람이 처리**한다.
- 사이트 자체가 포트폴리오다. 모바일 화면과 빠른 로딩을 우선한다.

## 4. 결정 기록

### D-01 순수 HTML + CSS로 만든다

- **배경**: 운영자는 C++·Java·Python·SQL은 다루지만 프론트엔드는 처음이다. 방학 동안 프론트 기초를 익혀야 한다.
- **대안**: (1) Tailwind CDN, (2) Next.js + Tailwind, (3) 순수 HTML + CSS
- **결정 근거**: 빌드 도구 없이 파일을 열면 바로 보이고 그대로 배포된다. CSS 기초(변수, Flex, Grid, 미디어쿼리)를 직접 익힐 수 있다. Tailwind CDN은 운영용으로 권장되지 않는다. 사례 페이지가 늘어나면 Next.js 전환을 다시 검토한다.

### D-02 문의는 크몽·숨고로만 받는다

- **배경**: 크몽·숨고는 외부 연락처 노출과 직거래 유도를 제재한다.
- **결정 근거**: 사이트에 전화번호·카카오톡·이메일을 넣지 않고 플랫폼 프로필 버튼만 둔다. 플랫폼에 이 사이트 링크를 올릴 수 있는지는 각 플랫폼 정책을 운영자가 직접 확인한다.

### D-03 깔끔한 화이트 스타일, 강조색 1개

- **결정 근거**: 의뢰인에게 신뢰감을 준다. 색은 `src/css/style.css` 맨 위 변수에 모아 강조색 하나만 바꿔도 전체 분위기가 바뀌게 한다.

### D-04 활동명은 임시 이름으로 시작

- `OO 웹스튜디오`를 자리표시로 쓴다. 정해지면 `index.html`에서 일괄 교체한다.

### D-05 포트폴리오는 실제로 만든 프로젝트 3건으로 채운다

- **배경**: 처음에는 smart-voca 1건과 가상 클라이언트 데모 2건(준비 중)을 두었다. 운영자에게는 이미 동작하는 프로젝트가 더 있다.
- **대안**: (1) 가상 데모를 먼저 만든다, (2) 기존 프로젝트를 사례로 쓴다
- **결정 근거**: "준비 중" 카드는 신뢰를 떨어뜨린다. 실제 동작하는 프로젝트가 더 설득력 있다. 의뢰인과 가장 가까운 순서로 둔다.
  1. **remodel-link**: 소규모 IT 외주 중개 서비스 (FastAPI, 토스페이먼츠 테스트 결제). 의뢰·제안·계약·결제·검수 흐름
  2. **잇다(ITDA)**: AI 자소서 코칭·모의면접 (React, Spring Boot, MySQL). Java 실력 증명
  3. **smart-voca**: 영어 단어 학습 회원제 서비스 (FastAPI)
- **스크린샷 방법**: 개발 DB를 건드리지 않는다. smart-voca와 remodel-link는 각 프로젝트의 `browser_check.py --keep`(임시 DB)으로, 잇다는 테스트 전용 스키마 `itda_it`와 가짜 LLM 서버로 띄워 지어낸 데이터로 찍는다. 화면의 AI 응답은 가짜 LLM의 고정 예시다.
- **휴대폰 화면**: 데스크톱 스크린샷을 줄이면 글자가 읽히지 않는다. 같은 방법으로 찍은 375px 화면을 `<picture>`로 720px 이하에서 바꿔 보여 준다 (`*-375.png`). 세로로 긴 화면이라 3:4 틀로 윗부분만 보인다.
- **링크**: smart-voca만 공개 저장소라 GitHub 링크를 단다. remodel-link와 잇다는 비공개 저장소라 링크를 달지 않는다.

### D-06 가게 홈페이지 데모는 카페·베이커리부터, 포트폴리오 안 폴더로 만든다

- **배경**: 사례 3건이 모두 회원제 서비스라 가게 홈페이지 의뢰인에게 와닿는 예시가 없다. 운영자가 받고 싶은 업종은 카페·베이커리와 미용실이다.
- **대안**: (1) 두 업종을 한 사이트에 합친다, (2) 업종별로 데모를 따로 만든다. 위치는 (a) 포트폴리오 안 폴더, (b) 별도 저장소·배포
- **결정 근거**: 사장님은 "같은 업종 사례"를 찾으므로 업종별로 따로 만든다. 카페는 보기만 하는 정적 페이지라 빨리 끝내고 (a) 포트폴리오 안 폴더에 둔다. 미용실은 예약 기능(FastAPI)으로 백엔드 차별점을 보여 주므로 (b) 별도 프로젝트로 나중에 만든다. 카페 분위기는 시안 3개 중 "따뜻한 내추럴"을 골랐고, 사진은 무료 사진 사이트에서 내려받아 쓴다.
- **포트폴리오 카드 위치**: 데모 카드는 사례 목록 맨 앞에 둔다. 배경: D-05가 정한 "의뢰인과 가까운 순서" 원칙. 결정 근거: 가게 사장님에게 가장 가까운 사례가 이 데모이기 때문이다.
