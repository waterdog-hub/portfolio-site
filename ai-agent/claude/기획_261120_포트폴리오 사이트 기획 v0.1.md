## 1. 목표

- 크몽·숨고 의뢰인이 서비스 페이지에서 링크를 눌러 들어와 **"이 사람에게 맡겨도 되겠다"** 고 판단하게 한다.
- 주력: **웹 제작** (홈페이지·랜딩페이지 + 예약·문의·관리자 같은 백엔드 기능).
- 차별점: 화면만 만드는 퍼블리셔와 달리 **백엔드(Python·SQL)까지 한 사람이 처리**한다.
- 사이트 자체가 포트폴리오다. 모바일 화면과 빠른 로딩을 우선한다.

## 4. 결정 기록

### D-01 순수 HTML + CSS로 만든다

- **배경**: 운영자는 C++·Java·Python·SQL은 다루지만 프론트엔드는 처음이다. 방학 동안 프론트 기초를 익혀야 한다.
- **대안**: (1) Tailwind CDN, (2) Next.js + Tailwind, (3) 순수 HTML + CSS
- **결정 근거**: 빌드 도구 없이 파일을 열면 바로 보이고 그대로 배포된다. CSS 기초(변수, Flex, Grid, 미디어쿼리)를 직접 익힐 수 있다. Tailwind CDN은 운영용으로 권장되지 않는다. 사례 페이지가 늘어나면 Next.js 전환을 다시 검토한다.

### D-02 문의는 크몽·숨고로만 받는다

- **배경**: 크몽·숨고는 외부 연락처 노출과 직거래 유도를 제재한다.
- **결정 근거**: 사이트에 전화번호·카카오톡·이메일을 넣지 않고 플랫폼 프로필 버튼만 둔다. 플랫폼에 이 사이트 링크를 올릴 수 있는지는 각 플랫폼 정책을 운영자가 직접 확인한다.

### D-03 깔끔한 화이트 스타일, 강조색 1개

- **결정 근거**: 의뢰인에게 신뢰감을 준다. 색은 `src/css/style.css` 맨 위 변수에 모아 강조색 하나만 바꿔도 전체 분위기가 바뀌게 한다.

### D-04 활동명은 임시 이름으로 시작

- `OO 웹스튜디오`를 자리표시로 쓴다. 정해지면 `index.html`에서 일괄 교체한다.

### D-05 포트폴리오는 실제로 만든 프로젝트 3건으로 채운다

- **배경**: 처음에는 smart-voca 1건과 가상 클라이언트 데모 2건(준비 중)을 두었다. 운영자에게는 이미 동작하는 프로젝트가 더 있다.
- **대안**: (1) 가상 데모를 먼저 만든다, (2) 기존 프로젝트를 사례로 쓴다
- **결정 근거**: "준비 중" 카드는 신뢰를 떨어뜨린다. 실제 동작하는 프로젝트가 더 설득력 있다. 의뢰인과 가장 가까운 순서로 둔다.
  1. **remodel-link**: 소규모 IT 외주 중개 서비스 (FastAPI, 토스페이먼츠 테스트 결제). 의뢰·제안·계약·결제·검수 흐름
  2. **잇다(ITDA)**: AI 자소서 코칭·모의면접 (React, Spring Boot, MySQL). Java 실력 증명
  3. **smart-voca**: 영어 단어 학습 회원제 서비스 (FastAPI)
- **스크린샷 방법**: 개발 DB를 건드리지 않는다. smart-voca와 remodel-link는 각 프로젝트의 `browser_check.py --keep`(임시 DB)으로, 잇다는 테스트 전용 스키마 `itda_it`와 가짜 LLM 서버로 띄워 지어낸 데이터로 찍는다. 화면의 AI 응답은 가짜 LLM의 고정 예시다.
- **휴대폰 화면**: 데스크톱 스크린샷을 줄이면 글자가 읽히지 않는다. 같은 방법으로 찍은 375px 화면을 `<picture>`로 720px 이하에서 바꿔 보여 준다 (`*-375.png`). 세로로 긴 화면이라 3:4 틀로 윗부분만 보인다.
- **링크**: smart-voca만 공개 저장소라 GitHub 링크를 단다. remodel-link와 잇다는 비공개 저장소라 링크를 달지 않는다.

### D-06 가게 홈페이지 데모는 카페·베이커리부터, 포트폴리오 안 폴더로 만든다

- **배경**: 사례 3건이 모두 회원제 서비스라 가게 홈페이지 의뢰인에게 와닿는 예시가 없다. 운영자가 받고 싶은 업종은 카페·베이커리와 미용실이다.
- **대안**: (1) 두 업종을 한 사이트에 합친다, (2) 업종별로 데모를 따로 만든다. 위치는 (a) 포트폴리오 안 폴더, (b) 별도 저장소·배포
- **결정 근거**: 사장님은 "같은 업종 사례"를 찾으므로 업종별로 따로 만든다. 카페는 보기만 하는 정적 페이지라 빨리 끝내고 (a) 포트폴리오 안 폴더에 둔다. 미용실은 예약 기능(FastAPI)으로 백엔드 차별점을 보여 주므로 (b) 별도 프로젝트로 나중에 만든다. 카페 분위기는 시안 3개 중 "따뜻한 내추럴"을 골랐고, 사진은 무료 사진 사이트에서 내려받아 쓴다.
- **포트폴리오 카드 위치**: 데모 카드는 사례 목록 맨 앞에 둔다. 배경: D-05가 정한 "의뢰인과 가까운 순서" 원칙. 결정 근거: 가게 사장님에게 가장 가까운 사례가 이 데모이기 때문이다.

### D-07 미용실 데모는 방문자마다 따로 쓰는 예약 데모로 만든다

- **배경**: 미용실 사장님에게는 "예쁜 홈페이지"보다 "예약을 받고 관리하는 기능"이 와닿는다. 손님 화면과 사장님 화면을 둘 다 보여 주기로 했다 (운영자 결정).
- **대안**: 체험 방식 (1) 방문자마다 예시 가게를 따로 만들고 24시간 뒤 지움, (2) 데모 가게 하나를 모두 함께 쓰고 매일 초기화. 만드는 방식 (a) smart-voca 구조(Jinja2 페이지 + JSON API + 바닐라 JS), (b) 페이지 이동만, (c) React 등으로 화면 분리
- **결정 근거**: (1)은 남이 넣은 장난 예약·이름이 보이지 않고, "방금 내가 넣은 예약이 사장님 화면에 뜨는" 핵심 장면이 확실하다. (a)는 검증된 구조라 빠르고 휴대폰에서 매끄러우며 빌드 도구가 없다(D-01 정신). 분위기는 시안 3개 중 "B 로즈 베이지"로 골라 하루밀(크림·갈색)과 구별한다.

### D-08 살롱 결 데모는 Render 무료 서버에 올리고 감시 핑으로 깨워 둔다 (2026-11-21)

- **배경**: 살롱 결은 서버가 계속 켜져 있어야 하는 FastAPI 앱이라 Netlify에 올릴 수 없다. 데이터는 원래 24시간만 남는 데모라 영구 디스크는 필요 없다.
- **대안**: (1) Render 무료(0원, 15분 동안 접속이 없으면 잠들고 깨는 데 약 1분) + 5분마다 `/api/v1/health`를 부르는 무료 감시 서비스, (2) Fly.io(월 약 $2.19, 항상 켜짐, 카드 등록과 Docker 필요), (3) Railway(월 $5부터)
- **결정 근거**: 운영자 결정. 돈이 들지 않고 Netlify처럼 GitHub `main`에 올리면 배포되는 방식이라 배우기 쉽다. 무료 750시간이면 한 대를 한 달 내내 켤 수 있다. 느린 게 문제가 되면 (2)로 옮긴다. 쿠키 없는 요청마다 예시 가게가 생기므로 IP별 생성 제한과 robots.txt를 함께 넣는다.
- **배포 후 확인 (2026-11-22)**: 방문자 IP는 Cloudflare가 덮어쓰는 `True-Client-IP` 헤더로 판별한다. 요청마다 IP 헤더를 다르게 꾸며 보내도 같은 IP로 세어져 정해진 횟수에서 429로 막혔다. 쿠키는 `Secure`로 내려온다. 저장소는 공개로 만들어 포트폴리오 카드에 GitHub 링크를 단다 (비공개 저장소는 링크하지 않는다는 D-05와 맞다).

### D-09 데모를 3개 이상으로 늘리고, 새 데모는 서버 없이 브라우저 안에서 동작하게 만든다 (2026-11-21)

- **배경**: 상담 중 "작업물 보여 주세요"에 링크 2~3개를 바로 보내야 한다. 받고 싶은 의뢰인은 음식점·학원 같은 동네 소상공인이다 (운영자). 데모는 하루밀(카페)과 살롱 결(미용실)뿐이라 학원과 음식점을 더 만든다 (학원 먼저). Render 무료 750시간은 서버 한 대분이라, 서버 데모를 하나 더 두면 둘 중 하나는 잠들어 첫 접속이 약 1분 걸린다.
- **대안**: (A) 포트폴리오 안 정적 페이지 + 방문자 브라우저(localStorage) 저장, (B) 살롱 결 같은 별도 FastAPI 서버, (C) 살롱 결 서버에 함께 얹기
- **결정 근거**: 운영자 결정 (A). 링크가 바로 열리는 것이 이 데모의 목적에 가장 중요하고, 0원이며, 방문자마다 데이터가 자동으로 나뉜다. "서버까지 한다"는 차별점은 살롱 결이 이미 보여 준다. 화면에 "데모라 브라우저에만 저장, 실제로는 서버 저장·알림톡"이라고 밝힌다.

### D-10 학원 데모는 보습학원, 시안 A 신뢰 네이비 + C 시간표 줄 (2026-11-21)

- **배경**: 학원 홈페이지를 보는 사람은 학부모다. 핵심 기능은 상담 신청과 원장님의 상담 관리다.
- **대안**: 업종 (1) 초·중등 보습학원, (2) 예체능. 분위기 시안 A 신뢰 네이비, B 산뜻한 그린, C 모던 그레이 + 오렌지
- **결정 근거**: 운영자 결정. 보습학원은 의뢰가 가장 많고 기존 데모 두 개(따뜻하고 예쁜 가게)와 분위기가 확실히 다르다. A의 정돈된 정보형 화면에 C처럼 과목·요일·시간·남은 자리를 한 줄씩 보여 준다. 지어낸 학부모 후기·성적 사례는 "가짜 후기"로 보일 수 있어 넣지 않는다.

### D-11 PREMIUM은 "별도 견적" 대신 "150만 원~"으로 적는다 (2026-11-21)

- **배경**: 크몽 시세와 가격표를 비교했다. 랜딩페이지 평균 약 49만 원(신규 판매자는 11만~29만 원대 시작), 홈페이지 평균 약 70만~80만 원, 예약·관리자 기능은 180만 원 이상 (크몽 비용 안내 글과 상품 페이지, 출처마다 수치가 조금 다르다).
- **대안**: (1) PREMIUM "별도 견적" 유지, (2) 시작가를 숫자로 적는다
- **결정 근거**: 운영자 결정 (2). 크몽 패키지 3단은 금액이 있어야 등록되고, "별도 견적"은 사장님이 비싸다고 느껴 문의를 망설이게 한다. 시장 기준보다 조금 낮은 150만 원에서 시작한다. STANDARD 30만 원·DELUXE 80만 원은 신규 판매자에게 적절해 그대로 둔다. 데모와 짝: 하루밀 = STANDARD, 바른길 학원 = DELUXE, 살롱 결 = PREMIUM.

### D-12 음식점 데모는 한식 밥집, 사장님 메뉴 직접 관리, 시안 A 먹색 + 한지 (2026-11-21)

- **배경**: 데모마다 다른 기능을 보여 줘야 한다. 음식점 사장님이 가장 자주 묻는 것은 "메뉴·가격을 직접 고칠 수 있나요?"다.
- **대안**: 기능 (1) 보기만 하는 홈페이지(하루밀과 겹침), (2) 단체·포장 주문 문의(학원과 겹침), (3) 사장님 메뉴 직접 관리. 업종 한식 밥집 / 고깃집 / 분식·국밥. 분위기 시안 A 먹색 + 한지, B 된장 주황 + 칠판, C 쑥색 + 흰색
- **결정 근거**: 운영자 결정 (3)·한식 밥집·A. 오늘의 백반과 품절이 매일 일어나는 업종이라 "품절을 누르면 손님 화면에 바로 뜨는" 장면이 가장 자연스럽다. 메뉴 사진도 사장님이 올릴 수 있게 한다 (운영자). 사진은 브라우저에서 줄여 localStorage에 넣고 올린 사진은 10장까지로 제한한다 (Claude 결정, 저장 공간이 넘쳐 데모가 깨지지 않게). 가격표에서는 DELUXE 예시다.

### D-13 미리 만든 시안 8종을 골라 사게 한다 (2026-11-27)

- **배경**: 크몽에서 홈페이지 제작으로 수익을 낸다. 시안을 미리 만들어 고객이 고르게 하면 상담과 시안 단계가 짧아져 빨리 팔고 납품할 수 있다 (운영자).
- **대안**: 업종별 / 스타일별 시안, 보여 주는 곳(포트폴리오 링크 / 크몽 이미지만 / 둘 다), 원본 위치(이 공개 저장소 / 별도 비공개 저장소)
- **결정 근거**: 운영자 결정. 업종별 8개, 분위기는 서로 다르게, 크몽 상세페이지 이미지로만, 원본은 별도 비공개 저장소. 기존 데모 4개는 시안 목록에 넣지 않는다. 세부 결정은 시안 기획서의 D-T1~D-T5.
